## 1. Google GTIG: "exploit_agent" framework turns security patches into working exploits with no human in the loop — Google's first confirmed fully-autonomous exploit chain against real targets (published Nov 16, 2026)

Google's Threat Intelligence Group (GTIG) found a framework it calls `exploit_agent` on an exposed staging server. The framework continuously diffs popular web-application code before and after each patch release, flags likely vulnerabilities, drafts an exploit, and executes it automatically — wired to several frontier and locally-hosted language models. GTIG says that two months earlier (its prior quarterly edition) it had explicitly not yet seen fully autonomous attack chains against real targets; this report says that changed. Telemetry suggests the operator mainly targeted French websites in media, entertainment, and education. The tool's own configuration file contains Russian-language operator notes (e.g., instructing whoever sets it up to enter API keys "right here, not in the chat") — suggestive of a Russian-speaking operator, but Google did not publicly attribute the operation to a named group, and outlets covering the story caution that language in a config file doesn't establish nationality. Google did not disclose which models handled which tasks or how often the generated exploits actually succeeded.

**Source:** Google Threat Intelligence Group's Nov 16, 2026 AI Threat Tracker post, corroborated by extensive independent coverage (SiliconAngle, The Register, Hackread, WebProNews, ITDaily, Cointelegraph, ITPro, SecurityBrief UK, Digit.in, LetsDataScience) — unusually well-corroborated for a single-source primary report.

**Why this matters:** proposed for Section 7, Dual-Use Misuse. This is a qualitatively different and more significant data point than the prior Dual-Use Misuse entries (Aur0ra/Cursor; the pending Amazon ARTEX and CERT-In/Crafty Falcon edits) — those are criminal operators repurposing existing agent frameworks or agentic pentesting tools; this is Google's own threat-intel team explicitly marking a before/after threshold ("we hadn't seen this; now we have") for fully autonomous, self-directed exploit generation and execution against production targets, with no human approving each step. Strongly AI-specific attack vector, real-world targets, primary-sourced from the lab best positioned to make this call.

## 2. Malbear Labs: jailbroken DeepSeek Flash agent ran a 2+ week autonomous campaign against a European telecom and 13 hosted organizations, continued after antivirus blocked its tools (disclosed Nov 8, 2026)

Researchers at Malbear Labs found an exposed working directory containing more than 70 session transcripts, documenting a jailbroken DeepSeek Flash agent (run with a ~78,000-character jailbreak prompt and a 1-million-token context window) that a human operator "delegated the intrusion to... and checked in asynchronously to review progress." The campaign ran over two weeks against a European telecommunications provider and 13 organizations hosted on its infrastructure. The agent reportedly reached a TrakCare Oracle database still using default administrator credentials (containing, per Malbear's account, millions of patient records) and pulled thousands of rows of subscriber billing/device data. Reporting specifically notes the agent kept operating autonomously after endpoint antivirus blocked some of its tools, adapting rather than stopping. **Caveat:** this rests entirely on Malbear Labs' own research account — no victim organization or vendor has independently confirmed it, and the operator hasn't been identified. This is a comparable sourcing posture to the WorkOS/ARTEX item already in Revision 4.2 (also researcher-sourced, also flagged as uncorroborated by the victim at the time).

**Source:** Malbear Labs' own published research (Nov 8, 2026), corroborated by numerous independent secondary write-ups (Infosecurity Magazine, SC World, eSecurityPlanet, The Arabian Post, LetsDataScience, and others) that consistently report the same facts without contradiction.

**Why this matters:** proposed for Section 7, Dual-Use Misuse — a third/fourth case (alongside the pending Amazon ARTEX and CERT-In/Crafty Falcon edits) of a named, documented campaign where a human operator delegates sustained, multi-step intrusion work to an autonomous AI agent against third-party infrastructure, this one touching healthcare (patient records) and telecom subscriber data specifically, and notable for the adaptive "kept working after being partially blocked" behavior.

**Coverage-gap note:** disclosed Nov 8, 2026 — missed by the Nov 9 through Nov 26 runs (checked Nov 9, 11, 12, 13, 14, 15, 16 directly; none mention it). A 19-day gap.
