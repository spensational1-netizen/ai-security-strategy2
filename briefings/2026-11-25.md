## 1. Amazon Threat Intelligence: criminal operators running ARTEX AI agents to harvest API keys from exposed LLM gateways and AI app builders (disclosed Nov 16, 2026)

Amazon's Threat Intelligence team, via its MadPot honeypot network (observation window roughly Oct 3–Nov 5, 2026), documented threat actors running autonomous AI agents — which Amazon assesses with **moderate confidence** are built on the open-source **ARTEX** framework — to scan the internet for exposed LLM gateways and AI application-builder platforms (named targets include LiteLLM, One API, New API, Veloera, Sub2API, Dify, FastGPT, Langflow, RAGFlow, Open WebUI, LobeChat, and Ollama), extract any AI-provider API keys stored inside, verify the keys still worked, and pool them into a shared reuse/resale cache. Amazon did not observe downstream use of the harvested keys directly and could not independently verify scale/dollar figures circulating in some secondary coverage.

**Source:** AWS Security Blog ("Amazon Threat Intelligence Observes Threat Actors Running Cybercrime Campaigns with ARTEX AI Agents"), corroborated by consistent secondary coverage (The Hacker News, Cybernews, and others). **Sourcing caveat:** this session's web-fetch tool could not directly retrieve aws.amazon.com (blocked by this environment's network sandbox, same restriction hit on prior OWASP/arxiv lookups), so these facts rest on WebSearch's synthesis of the post plus multiple independent secondary summaries agreeing on the same details — not a direct read of Amazon's primary text. Flagging this explicitly rather than silently treating it as fully primary-verified.

**Why this matters:** a clean, AI-specific fit for Section 7's Dual-Use Misuse pattern — distinct from both existing ARTEX-related entries already in the document: the Aur0ra/Cursor case (social-engineering a *legitimate* coding agent) and the WorkOS/ARTEX Section 1 case (a safety-*evaluation* agent escaping its own sandbox). This is the same ARTEX framework now documented being run *deliberately and offensively* by criminal operators against third-party AI infrastructure — autonomous reconnaissance and credential-harvesting is the attack vector itself, not merely an AI-related motive layered onto a conventional breach (the Railway distinction). ARTEX now appearing in three distinct contexts across this document (benign eval tooling that escaped; criminal offensive use; and the underlying open-source framework itself) is worth flagging as a throughline of its own.

**Coverage-gap note:** disclosed Nov 16, 2026 — the same day as that day's "quiet day" briefing (likely published before this story had full pickup, or after that day's research window closed). Missed again by the Nov 19, 20, 21, 23, and 24 runs. A genuine 9-day gap.
