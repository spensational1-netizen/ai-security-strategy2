# AI Security Briefing — November 21, 2026

**Bottom line:** Two genuinely new, well-sourced supply-chain incidents surfaced today, both proposed as new Row 1 (Model) precedents — and both represent coverage gaps this routine should have caught sooner.

---

## 1. Microsoft "agent-framework" PyPI supply-chain compromise (disclosed Nov 17, 2026)

Two malicious versions of Microsoft's official `agent-framework` Python SDK (used to build Azure AI agents) were published to PyPI via what Wiz assesses was a compromised Microsoft code-signing certificate — a genuinely valid credential, not a typosquat. Each malicious release dropped a `.pth` file that installs a credential stealer, running on every Python interpreter start regardless of whether the package was ever imported. Removed within about an hour; Microsoft hasn't published a root cause yet.

**Source:** [Wiz](https://www.wiz.io/blog/malicious-version-of-microsofts-agent-framework-published-to-pypi)

**Why this matters:** a textbook agentic supply-chain attack (ASI04 / MAESTRO Row 1) with a twist — the attacker had a genuinely valid signing credential, meaning normal signature-verification wouldn't have caught it. Proposed as a new Row 1 precedent.

**Coverage-gap note:** this broke Nov 17 — 3 days before Nov 20's "quiet day" check and 4 days before today. Both the Nov 19 and Nov 20 runs were explicitly catching up after the Nov 16-18 trigger outage, and neither surfaced it despite that. Flagging honestly rather than treating today as a same-day catch.

---

## 2. Fireworks AI vendor-key compromise → trojanized Cursor extension → Uber driver-data breach (widened Nov 9-17, 2026; underlying incident Oct 29-Nov 1)

An attacker compromised Fireworks AI (an AI inference vendor used by Cursor, Uber, Notion, and others), obtained a Cursor-issued access key, and used it to pull coding-agent session traces containing unredacted credentials. Those credentials let the attacker publish a trojanized copy of Anthropic's Claude Code extension to Cursor's own marketplace — live for ~11 hours, reaching an estimated ~5,000 users. Separately, Uber is notifying 149,346 drivers that names, addresses, DOBs, and driver's license numbers were exposed in the underlying Fireworks breach.

**Sources:** [Prophet Security](https://www.prophetsecurity.ai/blog/fireworks-ai-breach) | [news.lavx.hu](https://news.lavx.hu/article/cursor-says-stolen-fireworks-ai-key-led-to-trojanized-claude-code-extension-incident) | [Panorays](https://panorays.com/blog/uber-data-breach/)

**Why this matters:** a second, distinct inbound supply-chain mechanism for Row 1 — a compromised vendor credential (not a signing cert) weaponized through a trusted extension marketplace. Proposed as a second new Row 1 precedent.

**Coverage-gap note:** this is a bigger miss than #1. Checked back through the Nov 9 and Nov 16 "quiet day" briefings specifically — neither mentions Fireworks AI at all, despite Fireworks's own Oct 9 and Nov 9 bulletins falling squarely in that window. The actionable, MAESTRO-mappable specifics (the Cursor extension and Uber angle) only became clear with Fireworks's Nov 17 update, which is what this proposed edit is based on — not proposing to backdate the whole multi-week saga, just this well-sourced mechanism and its named impact.
