## 1. AWS discloses argument-injection flaw in its own security-agent-mcp-server — new, in-window Row 5 precedent

AWS Security Bulletin 2026-121 (Oct 1, 2026, CVE-2026-97662, CVSS 8.2 High) disclosed an argument-injection vulnerability in security-agent-mcp-server's diff-scan operation: a crafted reference value could be interpreted as a command-line option instead of a revision, letting a context-dependent actor create, overwrite, or truncate arbitrary files outside the intended workspace. Affects versions 0.1.1–0.1.x; fixed in 0.2.0.

- Source: [AWS Security Bulletin 2026-121](https://aws.amazon.com/security/security-bulletins/2026-121-aws/), [Threat Radar](https://radar.offseq.com/threat/cve-2026-97662-argument-injection-in-aws-security-agent-mcp-server-diff-scan-1d6c1e2d7ff405d0)
- **Why this matters:** This is Row 5's third precedent on its own — a flaw in an AWS-maintained security-tooling MCP server, distinct from the existing LiteLLM gateway bypass and MCP Python SDK OAuth flaw. Combined with item 2 below (if approved for backdating), Row 5 would reach 4 precedents and get its own Appendix A structure for the first time.

## 2. Coverage-gap flag: Obot MCP platform shipped a critical (CVSS 9.8) unauthenticated-by-default Docker deployment — Spencer's call on backdating

CVE-2026-101065 was published Sept 27, 2026 and was missed in coverage at the time. Obot's documented Docker quickstart starts the container listening on 0.0.0.0:8080 with authentication disabled by default — any network-accessible attacker gets full control of the Obot API/UI, can register malicious MCP servers, and via the container's mounted Docker socket, achieve arbitrary command execution and full host compromise. This is the highest CVSS score among Row 5's candidate precedents, and mirrors the same "insecure-default-deployment" pattern as the Loom item proposed yesterday (different row, same lesson).

- Source: [The Hacker Wire](https://www.thehackerwire.com/cve-2026-101065-obot-platform-unauthenticated-admin-access-leads-to-host-compromise-via-docker-socket/), [Strix.ai](https://www.strix.ai/cve/CVE-2026-101065)

## 3. Coverage-gap flag: Unsloth Studio RCE from just inspecting a malicious Hugging Face model — Spencer's call on backdating

CVE-2026-93348's public write-up (Pillar Security) was published Sept 29, 2026 and was also missed at the time (the underlying flaw was privately reported and fixed back in June). Unsloth Studio's model picker enabled trust_remote_code=True by default when checking a model's config before loading weights — a malicious repo's config.json could point Transformers' AutoConfig at attacker-supplied Python files, which got imported and executed critically just from a user selecting/inspecting the model, before any inference happened.

- Source: [Pillar Security](https://www.pillar.security/blog/look-dont-load-model-inspection-in-unsloth-studio-leads-to-critical-arbitrary-code-execution), [Cybersecurity News](https://cybersecuritynews.com/unsloth-studio-rce-flaw/)
- **Why this matters:** This is a genuinely new attack vector for Row 1 — not outbound distillation or guardrail-stripping like the existing entries, but an inbound supply-chain RCE triggered by mere model inspection. If approved, it would become Row 1's 4th precedent and change which two items show inline (pushing the NSA/CISA/FBI advisory into the earlier-precedents list).
