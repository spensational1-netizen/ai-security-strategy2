# AI Security Briefing — October 20, 2026

**Bottom line:** Two items today — a same-day, well-corroborated attacker-wielded-AI-agent cybercrime campaign (Cairn, 100+ companies breached) proposed for Section 7, and a vendor bug-bounty finding (Vercel Sandbox domain-allowlist bypass) proposed as a new named attack vector in Section 3, Row 6 — not a precedent, since it's undisclosed-to-exploitation research, not an observed incident.

## 1. Cairn-driven breach of 100+ companies, including John Deere, SharkNinja, Cummins (NorForge/Reuters, Oct 19, 2026)

A single Chinese-speaking attacker used Cairn — an open-source multi-agent AI hacking-orchestration platform — to breach more than 100 companies' websites across the US, Canada, Australia, and Japan, out of 1,200+ attempts starting September 25. NorForge found the campaign by scanning for inadvertently internet-exposed Cairn control panels (~2 dozen identified in malicious use by early October). Reuters confirmed named victims including John Deere, SharkNinja, and Cummins. Intrusions averaged ~23 hours with the attacker specifying tactics in under 100 Chinese characters per target — minimal human effort per breach. Cost-per-success estimates vary by source (~$50 vs. NorForge's own ~$5/task-including-failures). Cairn's own author says the platform wasn't built for hacking.

**Why this matters:** This is a second, independently-sourced instance of the same pattern ARTEX established in Revision 3.5 — open/commercial AI-agent infrastructure materially lowering the skill and cost floor for multi-target criminal intrusion. Same judgment call as before: this is attacker-wielded AI against third parties, not an enterprise's own deployed agent malfunctioning, so it's proposed for Section 7 (as a third entry, alongside ARTEX) rather than forced into Section 3.

Source: NorForge; Reuters; GBHackers; Gizmodo.

## 2. Vercel Sandbox domain-allowlist bypass — "VerCellBreak" (AIR Security, ~Oct 12–13, 2026)

AIR Security, via Vercel's bug-bounty program, found a way for a compromised sandboxed agent to defeat Vercel Sandbox's domain-allowlist egress control. The agent presents a crafted mTLS client certificate while connecting to an allowed domain; the certificate's AIA field carries the actual secret, encoded, which reaches an attacker-controlled server during certificate-chain validation — so the traffic's apparent destination is allowlisted while the payload still exfiltrates. Vercel's own documentation separately acknowledges SNI-filtering bypasses via literal IPs or custom DNS resolvers; some SNI-bypass variants are treated as out of scope by Vercel's bug-bounty program. No confirmed real-world exploitation.

**Why this matters:** Maps to Section 3, Row 6 (Runtime Execution) — but as a named attack vector, not a new precedent, per the routine's own standing test for lab/vendor-disclosed findings with no confirmed in-the-wild exploitation. Row 6 doesn't currently have a "no named precedent yet" placeholder (unlike Rows 2, 3, 5); this would be its first.

**Flagging the date as approximate:** could not independently confirm AIR Security's own publish date — a secondary summary cites "as of October 13, 2026, no patch exists," which places it roughly a week before today's run. Treating this as a coverage gap rather than a same-day find.

Source: AIR Security ("VerCellBreak: How we escaped Vercel's hardened sandbox"); Vercel's sandbox-firewall documentation and blog.
