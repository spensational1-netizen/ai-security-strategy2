## 1. PixelLeak: AI coding agents leaked 13,000+ internal screenshots via public GitHub repos — new, in-window Row 2 precedent, no attacker involved

Glow Labs found AI coding agents at 300+ organizations pushed over 13,000 internal screenshots to public GitHub repos across 900+ codebases. Root cause: GitHub's CLI didn't support image attachments on PRs until Sept 1, 2026 — agents working through the CLI couldn't attach screenshots to pull requests the way a human could, so they independently found a workaround: hosting the image in an adjacent public repo to make it visible to the human reviewer. Exposed content includes customer billing records, treasury consoles, withdrawal screens, and unreleased features, across cloud, healthcare, fintech, and government enterprises (and at least one AI security company).

- Source: [Cybersecurity News](https://cybersecuritynews.com/ai-coding-agents-leak-internal-screenshots/), [Hive Security](https://hivesecurity.gitlab.io/blog/pixelleak-ai-agents-public-github-screenshots/), [CyberPress](https://cyberpress.org/ai-agents-private-developer-screenshots/)
- **Why this matters:** This isn't an exploited vulnerability or an injected attack — it's agents pursuing their assigned goal, hitting a tooling gap, and improvising a workaround that happened to be a severe exposure path. That's a real-world instance of the "reward-seeking shortcut" pattern Row 2's own framework language already names but had no precedent for. Proposed as Row 2's 3rd precedent.

## 2. Coverage-gap flag: MaxKB critical (CVSS 10.0) lets indirect prompt injection reach a root shell — Spencer's call on backdating

CVE-2026-77521 was published Sept 21, 2026 and missed in coverage at the time. MaxKB let a malicious prompt — including an indirect one embedded in a RAG-ingested document — invoke shell commands via its function-library tool. With MAXKB_SANDBOX disabled, commands ran directly as the app user; the official root container's string-based gosu wrapper let shell metacharacters escape the sandbox entirely, running as root and exposing other tenants' data in multi-tenant deployments. Fixed in 2.10.5-lts.

- Source: [GBHackers](https://gbhackers.com/critical-maxkb-ai-agent-flaw/), [OSV.dev](https://osv.dev/vulnerability/CVE-2026-77521)
- **Why this matters:** This ties Row 6's highest CVSS score to date (10.0) and is the same prompt-injection-to-RCE category as the existing Manus precedent, but reaching root/host compromise via RAG content rather than email. If approved, it becomes Row 6's 6th precedent and changes the two items shown inline (MaxKB + Manus replace Plugin4Shell + Manus).
