## Plugin4Shell: a shared SHA-pinning bypass hits four major AI coding agents at once

AIR researchers (Or Nevo, Dor Granat, Niv Hoffman) disclosed Sept 17 that Claude Code, OpenAI Codex, Google Gemini CLI, and GitHub Copilot all shared the same flawed assumption: SHA-pinning a plugin to a specific reviewed commit doesn't actually stop an attacker from redirecting the checkout, because git resolves branch names ahead of commit hashes. An attacker who controls a plugin's repository creates a branch named identically to the pinned SHA and sets it as default — the agent's background auto-update then silently checks out the malicious branch while still appearing to honor the pin. No user interaction is needed; the swap happens during routine auto-update, which is what makes it zero-click. AIR found the bug in May 2026 and disclosed to vendors the following month.

Patch outcomes diverged sharply: Anthropic patched Claude Code (2.1.179), OpenAI patched Codex (0.146.0), Google chose to deprecate Gemini CLI entirely rather than fix it (redirecting users to Antigravity CLI), and GitHub has not shipped a fix for Copilot and disputes the scope of a claimed mitigation. No exploitation in the wild has been reported.

**Source:** SecurityWeek — https://www.securityweek.com/in-other-news-ransomware-developer-sentenced-plugin4shell-ai-attack-critical-sap-flaw/ ; Help Net Security — https://www.helpnetsecurity.com/2026/09/18/plugin4shell-ai-coding-agents-vulnerability/ ; AIR Security (original disclosure) — https://www.air.security/blog-posts/plugin4shell

**Why this matters:** This is a fourth, distinct mechanism in the same "agent plumbing" sandbox-escape failure class the strategy doc already tracks (alongside GitSpawn, Kiro Powers, and the DeepSeek Harness CVE) — but it's notable specifically because four independent engineering teams held the identical flawed assumption about what SHA-pinning actually guarantees, and because the patch divergence is itself a data point: "this vendor patched" is not a permanent status, and Gemini CLI users specifically need a migration plan, not a patch-wait. Any client running these tools with plugin marketplaces enabled should confirm patch status today, not assume it's handled.

*Nothing else cleared the bar today: the OpenAI/Anthropic/Google safety-coordination story and Anthropic's September threat report are continuations of stories already covered (Sept 12 and Sept 14 briefings); no fresh named-practitioner commentary (Ken Yuang, Sumant Thakur, Ashu Kumar) surfaced; no new Lasso/CrowdStrike/Okta announcements beyond what's already in the doc.*
