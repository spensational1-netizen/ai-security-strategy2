## 1. LMCache unauthenticated RCE via pickle deserialization — new Row 6 precedent

JFrog's Security Research team (researcher Yuval Moravchick) disclosed CVE-2026-105192 on Oct 7, 2026 (JFSA-2026-001694382, CVSS 9.8, Critical) — no patch available as of disclosure, with public proof-of-concept code already released. LMCache, an open-source caching layer used to accelerate vLLM-based LLM serving, opens a ZeroMQ ROUTER socket on port 5555 by default when running in multiprocess (distributed) mode, with no CURVE, ZAP, password, or message authentication on that transport. Incoming messages are deserialized with Python pickle, so a single unauthenticated crafted message to port 5555 triggers arbitrary code execution. The transport defaults to localhost, but the CVSS 9.8 applies once an operator sets a routable `--host` address to connect distributed nodes — a configuration JFrog says is common in production multi-node deployments. Affects versions 0.3.9 through the current 0.5.5 release and the 0.5.6rc3 candidate. LMCache has not yet published its own advisory.

- Source: [JFrog Security Research](https://research.jfrog.com/vulnerabilities/lmcache-is-vulnerable-to-unauthenticated-remote-code-execution-via-pickle-deserialization-on-the-multiprocess-zmq-transport-cve-2026-105192-jfsa-2026-001694382/), [Cybersecurity News](https://cybersecuritynews.com/poc-lmcache-flaw/), [GBHackers](https://gbhackers.com/critical-lmcache-rce-vulnerability/)
- **Why this matters:** A distinct mechanism from every existing Row 6 entry — a classic unauthenticated-deserialization RCE in the LLM-serving infrastructure layer itself (the caching/acceleration tier beneath the agent, not the agent or its tools). No exploitation in the wild reported yet, but a public PoC exists and no patch does. Would become Row 6's 8th precedent and change which two items show inline for the first time since AWS AgentCore Harness was added.

## 2. Self-correction: DIVD's Zammad breach, now attributed by DIVD itself to an autonomous AI agent — new Row 7 precedent

This was excluded in the Oct 8 pending doc on the grounds that "no AI-agent involvement [was] described in available reporting," with an explicit note to reconsider if that changed. It has. DIVD (the Dutch Institute for Vulnerability Disclosure) was breached starting Sept 21, 2026, chaining two Zammad helpdesk-platform zero-days (CVE-2026-102489, CVE-2026-102490) to go from session hijack to root in seconds. DIVD's own assessment — drawn from observed behavior, not confirmed actor/model identification — attributes the intrusion to an autonomous AI agent: investigators cite verbose, self-explanatory comments left in the attack scripts and an uncoordinated password-spraying attempt that disrupted the attacker's own credential harvesting, both read as signatures of non-deterministic, machine-speed decision-making. DIVD itself calls the attack "loud and very, very messy." No actor or model has been publicly named.

- Source: [BleepingComputer](https://bleepingcomputer.com/news/security/divd-says-zammad-zero-days-enabled-ai-driven-network-breach), [Cloud Security Alliance](https://labs.cloudsecurityalliance.org/research/csa-research-note-agentic-zero-day-chain-zammad-20261003-csa/), [Security Affairs](https://securityaffairs.com/?p=200126)
- **Why this matters:** Distinct from the ARTEX item (an attacker's own offensive tool wielded against third parties, properly excluded from Section 3) — this is an autonomous agent's own operational behavior during an intrusion being used as the attribution evidence, closer in kind to the "Tens of thousands of incidents" and AWS Loom entries already in Row 7. Chronologically the oldest of the row's precedents (Sept 21), so it wouldn't change the two-most-recent-inline pair if approved.

*Noted and excluded:* "Autonomous AI Agents Compromise Thousands of Credentials in Under Six Hours" resurfaced in an aggregator piece but is a September disclosure in the same attacker-wielded-AI category as ARTEX, with less depth. PoeLLM / "Canto Incognito" (Lumen Black Lotus Labs, Oct 7) — a cryptomining botnet hitting 3,400+ servers running exposed LiteLLM/Ollama/Gotenberg/Gitea — traces to an already-patched LiteLLM flaw (fixed May 2026); this is patch-hygiene exploitation, not an agent-architecture failure. Anthropic's OSS Scanner (Oct 9) is a defensive tool launch, not an incident. Anthropic's Cyber Verification Program resurfaced again but remains the same stale June 2026 story already excluded Oct 7.
