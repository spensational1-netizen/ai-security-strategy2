## 1. MCP TypeScript SDK — OAuth client credential-exposure flaw (CVE-2026-104850, GHSA-6qxp-vccf-f47h)

Published October 6, 2026 (CVSS 7.5, High). The official `@modelcontextprotocol/sdk` TypeScript client, versions 1.12.0–1.30.x and 2.0.0–2.1.x, let the MCP *server* a client connected to decide which OAuth authorization server received that client's stored credentials. A malicious or compromised MCP server could name its own authorization endpoint in its protected-resource metadata, and — with no user interaction — the client would send it the refresh token and client secret from an earlier legitimate sign-in. Fixed in SDK 1.31.0 / client 2.2.0; versions 2.0.0–2.1.0 already had a partial check (`expectedIssuer`) usable as an interim mitigation on 1.x by only connecting to trusted MCP servers. No evidence of in-the-wild exploitation or public proof-of-concept.

This is a **different** advisory from the MCP *Python* SDK OAuth flaw already in the strategy doc (GHSA-qx49-fqc8-xw99, Sept 29) — same class of bug, same official org, different SDK and different GitHub advisory.

**Why this matters:** Maps to Section 3, Row 5 (Tools & Skills/MCP). This is the second OAuth-trust-boundary failure in an official MCP SDK in under two weeks (Python Sept 29, TypeScript Oct 6) — the pattern is no longer "one SDK had a bug," it's "the client-side trust model for MCP OAuth was under-specified across both reference implementations."

**Flagging as a coverage gap, not a same-day find:** this published Oct 6 — six days before today's run, and before the Oct 7–11 runs that should have caught it. It was not found mentioned or excluded in any prior briefing; it simply wasn't surfaced in a daily search until today.

Sources: GitHub Security Advisory GHSA-6qxp-vccf-f47h; GitLab Advisory Database; OpenCVE/Mend/Vulert CVE summaries.
